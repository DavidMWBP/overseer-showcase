# Layout and development

## Layout

- `packages/daemon` — Fastify daemon: REST and WebSocket under `/api`, MCP server under `/mcp`, `node:sqlite` state, beads bridge, git worktree and merge operations, session manager, lifecycle state machine, harness adapters.
- `packages/web` — React UI (rail, Board, Office with its review drawer, Chat, Review, Usage, Discussions, Evidence, Setup and Plan); the Office needs-you strip has a Plans row with the draft count and opens every plan (newest first, any status), so a draft, approved or discarded plan is all reachable there. Talks only to `/api`.
- `packages/shared` — API types shared by both.

## Development

Do not commit anything that names the user, their employer or a managed repository's host, or contains product or customer text, account names, email addresses, home paths or likeness references. Use fictional stand-ins. The daemon privacy test scans tracked files against the machine-local denylist at `~/.overseer/private-terms.txt` (one term per line); it reports a skip when the file is missing, and the list itself stays outside the repository.

```bash
pnpm typecheck      # all packages
pnpm test           # all packages; runs each package's test script, so for the daemon this is the fast run and the three slow files are skipped (see below); uses real git repos, real SQLite and an in-process MCP client; every vitest run is capped at 4 workers (`OVERSEER_VITEST_MAX_FORKS` overrides) so concurrent runs share the 16-thread box
```

`pnpm --filter @overseer/daemon test` only covers the fast daemon files — `vitest.config.ts`'s default `include` minus the three files listed in its `slowTestFiles`, `src/beads/beads.live.test.ts` (whose ~25 real bd calls share one repo and cannot run concurrently) and `src/daemon-restart.integration.test.ts` (which waits out a hardcoded busy-port retry window), and `src/api/evidence.performance.test.ts` (which creates 11,000- and 5,000-file temporary trees). The first two spawn real processes (git, bd and a second daemon) and can be flaky under load. `pnpm --filter @overseer/daemon run test:slow` runs all three. "The daemon tests pass" means both: `pnpm --filter @overseer/daemon test && pnpm --filter @overseer/daemon run test:slow`; a Definition of Done that only names the first command is checking a subset. `src/vitest-config.test.ts` asserts every `src/**/*.test.ts` file is reached by exactly one of the two, so a file can't be silently skipped by both.

Focused runs: `pnpm --filter @overseer/daemon test <file>` runs one daemon test file, whichever list it's in — a wrapper script checks the file against `slowTestFiles` and switches to `--mode slow` automatically, so the caller doesn't have to guess and hit `No test files found`; naming files from both lists in the same call fails, naming the two commands to run instead; a bare substring under the plain `test` command reaches only the fast files it matches and silently skips any slow file the same substring would also match, so filtering by substring needs `pnpm --filter @overseer/daemon test:slow <filter>` too for the slow side; and `pnpm --filter @overseer/daemon test:slow <filter>` stays slow, so a bare substring such as `daemon-restart` still reaches the slow files rather than being downgraded to the fast run. `pnpm --filter @overseer/web test -- <pattern>` for the web package.

Opt-in tests and tools:

- `OVERSEER_LIVE=1` runs the live adapter and beads tests against the real CLIs (spends tokens).
- `OVERSEER_RECORD=1` lets the beads live test rewrite its fixtures.
- `pnpm --filter @overseer/daemon record:claude|opencode|codex` records a real event stream into `src/harness/fixtures/`.
- `pnpm --filter @overseer/daemon eval:prompt` scores a prompt file against a directory of cases (spends tokens). Defaults: `--prompt prompts/orchestrator.md`, `--cases evals/orchestrator/cases/train`, `--k 3` runs per case, `--max-run-usd 5` per orchestrator run and `--judge-model sonnet`; relative paths resolve from `packages/daemon`. The cases are split into `packages/daemon/evals/orchestrator/cases/train/` (20, the default) and `holdout/` (10); `--cases` reads only the `*.json` files directly in the directory it names, so the holdout set is scored with `--cases evals/orchestrator/cases/holdout`, and a holdout case is never shown to anything that rewrites a prompt, so its score measures a rewrite on cases it was not written against. Each case quotes the `docs/lessons.md` entry it tests and holds the input the orchestrator receives (a chat message with its `[repo: <id>]` prefix, or an `[Overseer]` notice), the repos and batches its fresh-session preamble names, fixture replies per MCP tool with a `default` for anything unlisted; repeated matching calls consume duplicate fixtures in listed order, then reuse the first match, and a `bd create` reply carries the title the model submitted, as does every later reply naming the bead that create made. The cases include assertions: exact checks on the recorded tool calls (`called`, `not_called`, `order`, `arg_contains`, and `no_message` for a turn that must stay silent) and `rubric` lines that a separate judge session grades without seeing the prompt. Each run starts the orchestrator the way the daemon does, on the live orchestrator's model, effort and account (read from the live database read-only), with a temp database and working directory, against a mock `overseer` MCP server that answers from the fixtures and never runs a tool (it records raw arguments sent by the model and uses schema-parsed arguments, including defaults, only to select fixtures; refused calls are also recorded, so `not_called` counts the attempt), and with `--strict-mcp-config`, `--max-budget-usd` and `--no-session-persistence`, so no session is saved under your Claude config (the empty folder the CLI still makes under `~/.claude/projects` for each run's temp directory is removed after the run, and kept only if it holds a file); the eval session restricts built-in tools to Bash, Read, Grep and Glob, blocks network commands, local-port probes, UNC paths, shell writes and the forms of allowed read commands that run another program (such as sed's `e` command), and refuses file-write paths outside its temporary cwd; a one-line probe on that account has to answer before any run. A run counts only when its turn completed cleanly (no error, no timeout, no spending cap reached), and a case's pass rate is the share of its K runs that did and in which every assertion passed; the prompt's score is the mean pass rate. The judge must quote the transcript for every pass and for every fail that rests on something the run did, and a quote that is not in the transcript fails the line; a judge reply with no readable grades gets one more, fresh judge session before its lines fail. The report (`report.json`, `report.md` and one transcript per run, with the prompt's character count and each run's cost and duration) goes to `~/.overseer/evidence/prompt-evals/<run id>/`, which the Evidence view lists.
- `pnpm --filter @overseer/daemon eval:loop` runs the shortening loop on a prompt (spends tokens). Defaults: `--prompt prompts/orchestrator.md`, `--train evals/orchestrator/cases/train`, `--holdout evals/orchestrator/cases/holdout`, `--k 3`, `--rounds 5`, `--budget-usd 300`, `--target-chars 30000`, `--target-holdout 0.9` and `--max-rewrite-usd 10` per rewriter call; `--max-run-usd` and `--judge-model` go to each eval. Round 0 is the starting prompt's train and holdout scores, scored with `eval:prompt` or taken from `--train-report` and `--holdout-report`, which are refused when their `prompt_chars` does not match the prompt file or their `k` does not match `--k`. Each round a fresh rewriter session on the live orchestrator's model, effort and account (no tools, no MCP server, a temp directory, Git's system and global configuration switched off) writes one shorter candidate from the current best prompt, the train cases and the transcripts and failing checks of the failed train runs; it may reword, merge or drop any rule but must keep what the train cases test, and it never sees a holdout case, transcript or per-case result. Every candidate is scored on train and holdout at K, and it is kept only when it is shorter than the current best and scores at least as well on both train and holdout; two scores within 1e-9 count as equal, since the same passes averaged in another order can differ in the last bit. Every `claude -p` call the loop and the eval make (the probe, a judge, a rewrite) is stopped after 30 minutes and recorded as a failure. The loop stops when the best reaches the holdout target at or under the character target, after the last round, when the spend (rewriter, runs and judges) reaches the budget, or when the next round's estimate (the mean round cost so far, or before round 1 the round-0 cost plus the rewriter cap) would pass it. Every candidate, its scores and cost, whether it was kept and why, the winner (`winner.md`) and `report.md` go to `~/.overseer/evidence/prompt-evals/loop-<run id>/`; the loop never writes to `prompts/`.
